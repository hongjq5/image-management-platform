# 发布副本与历史隔离

## 历史背景

2026-09-19 的开发副本检查记录曾发现旧配置和 HTTP 客户端文件中有口令及会话字面量，因此采用独立发布副本，保留开发副本与上游来源，不直接上传旧开发历史。本节仅描述当时的检查结论，不代表本次重新检查了开发副本全部历史。

`.gitignore` 不能消除旧提交里的内容。发布时应同时检查当前文件和将要上传的提交历史，不应仅凭当前配置已经外置就推送旧历史。

## 发布副本的范围

- 保留普通后端、前端、测试、空数据库结构、配置示例、CI 与文档。
- 不包含 DDD 参考版本、HTTP 客户端私有环境、真实本地配置、依赖目录、构建产物或业务数据。
- 保留上游来源说明及源码作者注释。当前未新增许可证，不据此推断再分发授权。
- 本地配置和演示账号应由使用者自行创建；示例图片只使用无个人数据的几何素材。

2026-10-09 对 `public-yu-picture` 的处理范围与验证结果另见 [发布脱敏说明](publish-sanitization.md)。历史扫描不能替代对新增文件和实际暂存区的检查。

## GitHub 发布

GitHub Desktop 导入本地目录只是本地管理；只有执行发布或推送并在 GitHub 上确认，才算完成上传。本文件不代表已经创建远程仓库、提交或推送。

仓库可见性由发布者选择。公开发布前应核对来源许可；私有仓库也不能保存真实凭据。详见 [安全说明](../SECURITY.md)。
