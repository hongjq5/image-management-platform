## 裁切器空白画布追踪

浏览器集成时发现 960 × 640 的团队图片可在上传预览显示，但裁切画布为空。检查已安装的 `vue-cropper 1.1.4` 源码确认：该版本不提供 `checkCrossOrigin` / `checkOrientation` 参数，也没有追加缓存 query；它先以匿名 CORS 加载图片，再发起一次 EXIF XHR，之后才生成本地画布图片。EXIF XHR 缺少网络错误处理，应用之前也没有处理图片加载失败事件。

使用本任务演示账号只读检查同一签名原图：无 Origin 请求与带本地 Origin 请求都返回 200、WebP、9362 字节；只有后者返回正确的 `Access-Control-Allow-Origin`，两者都没有 `Vary: Origin`。页面的普通预览先加载同一 URL，因此浏览器可能将不含 CORS 响应头的缓存用于后续裁切读取。检查和报告均未输出签名 URL 或账号凭据。

`ImageCropper.vue` 现在在弹窗打开后以 `mode: 'cors'`、`credentials: 'omit'`、`cache: 'no-store'` 获取原样签名 URL，再将本地 Blob URL 交给裁切器，避免复用普通预览缓存。关闭、卸载或更换图片会取消未完成请求并释放 Blob URL，旧响应不能覆盖新图片。图片解码成功前禁用编辑操作，加载失败显示可操作的提示，不再只显示空画布。

两项真实 SFC 回归先失败，随后修复通过，验证缓存隔离、签名参数不变、不发送应用 Cookie、解码后才能确认、资源回收、失败状态以及迟到响应隔离。最终真实团队图片浏览器复验由主任务记录。
